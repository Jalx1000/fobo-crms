# Tarea 8.4 — Nuevo endpoint `GET /api/v1/insurance/verify` para el agente WhatsApp

**Agente asignado:** `backend`
**Fase:** 08 — Agente WhatsApp
**Complejidad:** Alta
**Tiempo estimado:** 4h
**Dependencias:** Ninguna

---

## Objetivo

Crear `GET /api/v1/insurance/verify?ci_paciente=X&seguro_paciente=Y` que el agente de WhatsApp usa para verificar si un paciente tiene seguro activo, dado su cédula y el nombre de la aseguradora en texto libre. El endpoint debe buscar al paciente por su custom attribute `ci_paciente` en la tabla EAV `attribute_values`, luego delegar en `InsuranceService::verifyWithParams()`.

## Contexto

**Lo que ya existe y se reutiliza:**

- `InsuranceService::verifyWithParams(string $ci, string $seguroName): array` en `packages/Webkul/Admin/src/Services/InsuranceService.php` — ya hace la verificación dado CI + nombre de seguro en texto libre, sin necesitar `person_id`.
- `packages/Webkul/Admin/src/Http/Controllers/Api/InsuranceController.php` — ya tiene `POST /api/insurance/verify` bajo Sanctum. Se puede extender con un nuevo método.
- `packages/Webkul/Admin/src/Routes/Api/insurance.php` — registrado en `AdminServiceProvider` bajo `auth:sanctum + throttle:api`.
- Custom attributes: `ci_paciente` (tipo `text`) y `seguro_paciente` (tipo `select`) en tabla `attribute_values` con `entity_type = 'persons'`.

**Lo que falta:**

1. Lookup de `Person` por valor del custom attribute `ci_paciente` en `attribute_values`.
2. Nuevo método `verifyForAgent()` en `InsuranceController` que acepte `GET` con `ci_paciente` + `seguro_paciente` como query params.
3. Respuesta con la shape específica del agente (diferente a la respuesta interna del CRM).
4. Anti-enumeración: misma shape para "paciente no encontrado" y "sin seguro" (ver Tarea 8.5 para rate limiting y audit log).

**Parámetros del endpoint (confirmados por PO):**
- `ci_paciente` (string, requerido) — cédula del paciente
- `seguro_paciente` (string, requerido) — nombre de la aseguradora en texto libre

## Implementación

### 1. Nuevo método en InsuranceController

Archivo: `packages/Webkul/Admin/src/Http/Controllers/Api/InsuranceController.php`

Añadir al final de la clase, antes del cierre `}`:

```php
use Illuminate\Http\Request;
use Illuminate\Support\Facades\DB;
use Webkul\Attribute\Repositories\AttributeRepository;

// ─── Nuevo método ───────────────────────────────────────────────────────────

/**
 * GET /api/v1/insurance/verify
 *
 * Verifica si un paciente tiene seguro activo, buscándolo por CI y nombre de aseguradora.
 * Diseñado para el agente de WhatsApp. Responde con shape consistente (anti-enumeración).
 *
 * @param  Request  $request  ?ci_paciente=X&seguro_paciente=Y
 */
public function verifyForAgent(Request $request): \Illuminate\Http\JsonResponse
{
    $data = $request->validate([
        'ci_paciente'     => ['required', 'string', 'min:3', 'max:30'],
        'seguro_paciente' => ['required', 'string', 'min:2', 'max:100'],
    ]);

    $ci          = trim($data['ci_paciente']);
    $seguroName  = trim($data['seguro_paciente']);

    // ── Lookup EAV: buscar Person por ci_paciente ──────────────────────────
    $ciAttribute = app(AttributeRepository::class)
        ->findOneByField('code', 'ci_paciente');

    $person = null;

    if ($ciAttribute) {
        // attribute_values usa text_value para tipo 'text'
        $attributeValue = DB::table('attribute_values')
            ->where('attribute_id', $ciAttribute->id)
            ->where('entity_type', 'persons')
            ->where('text_value', $ci)
            ->first();

        if ($attributeValue) {
            $person = \Webkul\Contact\Models\Person::find($attributeValue->entity_id);
        }
    }

    // ── Verificar seguro ───────────────────────────────────────────────────
    $result = $this->insuranceService->verifyWithParams($ci, $seguroName);

    // ── Construir respuesta de agente ──────────────────────────────────────
    $hasInsurance = in_array($result['status'] ?? '', ['VIGENTE', 'EN_MORA']);

    if (! $hasInsurance) {
        // Anti-enumeración: misma shape para "no encontrado" y "sin seguro"
        return response()->json([
            'has_insurance'  => false,
            'patient_found'  => false,
        ]);
    }

    // Extraer datos del resultado del driver (estructura varía por aseguradora)
    $data = $result['data'] ?? [];

    return response()->json([
        'has_insurance'   => true,
        'insurance_name'  => $result['seguro_name'] ?? $seguroName,
        'policy_number'   => $this->extractField($data, ['POLIZA', 'NUMERO POLIZA', 'policy_number']) ?? null,
        'coverage_type'   => $this->extractField($data, ['TIPO COBERTURA', 'coverage_type', 'PLAN']) ?? 'dental',
        'valid_until'     => $this->extractField($data, ['VIGENCIA HASTA', 'VENCIMIENTO', 'valid_until']) ?? null,
        'covered_services'=> $this->extractField($data, ['SERVICIOS', 'covered_services']) ?? [],
        'patient_name'    => $person?->name
                            ?? $this->extractField($data, ['NOMBRE COMPLETO', 'NOMBRE', 'patient_name'])
                            ?? null,
        'patient_id'      => $person?->id,
    ]);
}

/**
 * Busca un campo en el array de datos del driver por múltiples claves posibles.
 * Los drivers devuelven keys diferentes según la aseguradora (NOMBRE COMPLETO, NOMBRE, etc.)
 */
private function extractField(array $data, array $keys): mixed
{
    foreach ($keys as $key) {
        // Búsqueda exacta
        if (isset($data[$key])) {
            return $data[$key];
        }
        // Búsqueda case-insensitive
        foreach ($data as $dataKey => $value) {
            if (strtolower($dataKey) === strtolower($key)) {
                return $value;
            }
        }
    }
    return null;
}
```

### 2. Nueva ruta

```php
Route::prefix('api')->group(function () {

        Route::get('insurance/verify', [InsuranceController::class, 'verifyForAgent'])
            ->name('api.v1.insurance.verify');
    });
});
```

Este archivo ya está cargado por `AdminServiceProvider` bajo `auth:sanctum + throttle:api`, por lo que la ruta hereda Sanctum automáticamente.

### 3. Lookup EAV — Explicación del patrón

La tabla `attribute_values` tiene esta estructura relevante:
```
entity_type | entity_id | attribute_id | text_value | boolean_value | integer_value | ...
persons     | 55        | <ci_attr_id> | "1234567"  | null          | null          | ...
```

Para tipo `text` (que es `ci_paciente`), el valor se almacena en `text_value`. La query:

```php
DB::table('attribute_values')
    ->where('attribute_id', $ciAttribute->id)
    ->where('entity_type', 'persons')
    ->where('text_value', $ci)
    ->first();
```

Devuelve la fila cuyo `entity_id` es el `id` del Person. Luego:

```php
$person = Person::find($attributeValue->entity_id);
```

### 4. Respuesta esperada

**Paciente con seguro activo (VIGENTE o EN_MORA):**

```json
{
  "has_insurance": true,
  "insurance_name": "Seguros Equinoccial",
  "policy_number": "POL-2025-00123",
  "coverage_type": "dental",
  "valid_until": "2026-12-31",
  "covered_services": [],
  "patient_name": "Adenilza Flores",
  "patient_id": 55
}
```

**Paciente no encontrado O sin seguro (anti-enumeración):**

```json
{
  "has_insurance": false,
  "patient_found": false
}
```

**Nota:** `patient_id` NUNCA se incluye cuando `has_insurance: false`. Ver Tarea 8.5 para los requerimientos de seguridad adicionales.

## Criterios de aceptación

- [ ] `GET /api/v1/insurance/verify?ci_paciente=X&seguro_paciente=Y` sin token devuelve `401 Unauthenticated`
- [ ] `GET /api/v1/insurance/verify` con token y CI + seguro válidos devuelve shape con `has_insurance: true` y `patient_id`
- [ ] `GET /api/v1/insurance/verify` con CI inexistente devuelve `{"has_insurance": false, "patient_found": false}`
- [ ] `GET /api/v1/insurance/verify` con CI existente pero sin seguro devuelve `{"has_insurance": false, "patient_found": false}` (anti-enumeración)
- [ ] La ruta está registrada bajo `GET /api/v1/insurance/verify` (no POST)
- [ ] Los parámetros de validación rechazan CI vacío (`min:3`) con `422`
- [ ] La respuesta positiva nunca incluye `patient_id` si `has_insurance` es false
