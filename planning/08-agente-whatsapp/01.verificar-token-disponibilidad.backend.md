## Objetivo

Confirmar dos preguntas abiertas que bloquean al agente de WhatsApp:

1. **P1 — Auth:** ¿El token `ODONTOKING_API_TOKEN` (Sanctum) tiene acceso a `GET /api/disponibilidad`?
2. **P2 — Parámetro `date`:** ¿El endpoint acepta múltiples fechas en una sola llamada o solo una fecha por request?

Documentar las respuestas con evidencia (curl o Tinker) y, si hay algún problema de acceso, aplicar el fix.

## Contexto

El agente de WhatsApp en `https://odontoking.wappy.dev` necesita consultar disponibilidad de doctores por fecha. Actualmente llama a `GET /api/doctors` (que no devuelve `end_time`) en vez de `GET /api/disponibilidad?doctorId=X&date=Y` (que sí devuelve `startTime` + `endTime`).

El fix es del lado del agente, pero antes hay que confirmar que el token funciona.

**Estado del código (ya investigado):**

- `GET /api/disponibilidad` está registrado en `routes/api.php` línea 136, dentro del grupo `Route::middleware('auth:sanctum')`.
- `GET /api/doctors` está registrado en `packages/Webkul/Doctor/src/Routes/api.php` bajo el middleware `api` (sin Sanctum). Accesible sin token.
- El controlador `ScheduleController::getDisponibilidad()` está en `app/Http/Controllers/Api/ScheduleController.php`. El parámetro `date` es validado como `date_format:Y-m-d` (un solo string, no array).

### Paso 3 — Confirmar P2: `date` acepta solo una fecha

Revisar `ScheduleController::getDisponibilidad()` en `app/Http/Controllers/Api/ScheduleController.php`:

```php
// Línea relevante del validador:
'date' => 'required|date_format:Y-m-d',
```

La validación es `required|date_format:Y-m-d` sobre un string único. **No acepta arrays.** El agente debe hacer N llamadas separadas, una por fecha.

Para consultar disponibilidad de 7 días, el agente hará:
```
GET /api/disponibilidad?doctorId=X&date=2026-05-24
GET /api/disponibilidad?doctorId=X&date=2026-05-25
...
GET /api/disponibilidad?doctorId=X&date=2026-05-30
```

## Hallazgos (completar al ejecutar la tarea)

### P1 — Auth (token Sanctum)

Verificación ejecutada 2026-05-24. La BD no es accesible desde fuera del contenedor Docker (resolución DNS falla al intentar conectar desde el host al contenedor `heaven_odontoking-bd`). La verificación vía Tinker requiere ejecutarse **dentro** del contenedor de la aplicación.

**Lo confirmado por análisis de código estático:**

- `routes/api.php` línea 134-137: `GET /api/disponibilidad` está dentro del grupo `Route::middleware('auth:sanctum')`. Cualquier request sin token `Bearer` recibe `401 Unauthenticated`.
- `GET /api/doctors` y `GET /api/doctors/{id}` están en `packages/Webkul/Doctor/src/Routes/api.php` bajo middleware `api` (sin Sanctum). **Accesibles sin token.**
- El guard usado es `auth:sanctum`, que en este proyecto resuelve contra `Webkul\User\Models\User` (el tokenable estándar de Krayin).

**Acción requerida (dentro del contenedor o desde la app en producción):**

```bash
# Verificar si el token 'whatsapp-agent' existe
php artisan tinker --execute="
use Laravel\Sanctum\PersonalAccessToken;
PersonalAccessToken::where('name', 'whatsapp-agent')->get(['id','name','tokenable_type','tokenable_id','last_used_at'])->each(fn(\$t) => dump(\$t->toArray()));
"

# Si no existe, crearlo:
php artisan tinker --execute="
use Webkul\User\Models\User;
\$user = User::find(1);
\$token = \$user->createToken('whatsapp-agent', ['*']);
echo 'TOKEN: ' . \$token->plainTextToken . PHP_EOL;
"
# Guardar el token en ODONTOKING_API_TOKEN en Easypanel (variables de entorno del agente)
```

**Estado P1:** [x] Confirmado por código que el endpoint requiere token Sanctum. Verificación de existencia del token pendiente de ejecución dentro del contenedor.

### P2 — Parámetro `date` (multi-fecha)

Confirmado por lectura directa de `app/Http/Controllers/Api/ScheduleController.php` línea 47-48:

```php
$validator = Validator::make($request->all(), [
    'doctorId' => 'required|integer',
    'date'     => 'required|date_format:Y-m-d',
]);
```

**El endpoint acepta exactamente una fecha por llamada** — string único con formato `Y-m-d`, no array. Si se pasa `date[]=...` o `dates=...`, falla la validación con 400.

### Acción recomendada al equipo del agente WhatsApp

1. **Usar `GET /api/disponibilidad`** en lugar de `GET /api/doctors` para consultar horarios disponibles.
2. **Incluir el token Bearer** en el header `Authorization`: el endpoint requiere Sanctum. El token debe estar en `ODONTOKING_API_TOKEN` en el entorno del agente.
3. **Una llamada por fecha**: para obtener disponibilidad de 7 días hay que hacer 7 requests `GET /api/disponibilidad?doctorId=X&date=YYYY-MM-DD`.
4. **La respuesta** incluye `startTime` y `endTime` (formato `H:i`), junto con `doctorId` y `date` — suficiente para el agente.
5. **Alternativa más simple**: `GET /api/doctors/{id}` (sin token, público) ya devuelve `schedule` con los próximos 6 días en un solo request, con slots que incluyen `start_time`, `end_time` y `status`. Ver tarea 8.7.
