## Diagnóstico de smd-insurance.blade.php

### Estructura actual

El archivo es un single-file Vue component registrado con `app.component('v-smd-insurance-tab', ...)`. Tiene dos cards:

1. **Card "Seguro médico"** — muestra estado, CI, aseguradora, fecha de verificación. Botones: "Verificar cobertura", "Borrar caché".
2. **Card "Estado en SMD"** — muestra estado de vinculación. Sub-estados: loading, vinculado (con datos SMD), no vinculado (con buscador manual).

### Problemas

#### A. Spinners ad-hoc (4 ocurrencias)

```html
<!-- L65 — Botón Verificar cobertura -->
<span v-if="insurance.verifying" class="animate-spin inline-block w-3.5 h-3.5 border-2 border-white border-t-transparent rounded-full"></span>

<!-- L134 — Botón Re-verificar vínculo -->
<span v-if="smd.reverifying" class="animate-spin inline-block w-3.5 h-3.5 border-2 border-gray-400 border-t-transparent rounded-full"></span>

<!-- L151 — Botón Sincronizar con SMD -->
<span v-if="smd.syncing" class="animate-spin inline-block w-3.5 h-3.5 border-2 border-white border-t-transparent rounded-full"></span>

<!-- L170 — Botón Buscar -->
<span v-if="smd.searching" class="animate-spin inline-block w-3 h-3 border-2 border-gray-400 border-t-transparent rounded-full"></span>
```

**Solución**: Reemplazar por `<x-admin::spinner>` con las clases de tamaño adecuadas:

```html
<!-- DESPUÉS -->
<x-admin::spinner v-if="insurance.verifying" class="w-4 h-4" color="white" />
```

Nota: `x-admin::spinner` es un componente Blade que se renderiza server-side. En templates Vue string esto no aplica. Sin embargo, `doctor-day-calendar.blade.php` usa `<x-admin::spinner>` dentro de `x-slot:footer` (que es Blade, no un template string Vue). En `smd-insurance.blade.php` el template está en un `<script type="text/x-template">` — aquí sí se puede usar `<x-admin::spinner>` porque el template se parsea por Blade antes de ser enviado al navegador.

Verificación: Los footers de los modales en `doctor-day-calendar.blade.php` L527-528 ya lo hacen así:
```html
<span v-else class="flex items-center gap-2"><x-admin::spinner /> Guardando...</span>
```

```html
        <div class="h-4 bg-gray-100 dark:bg-gray-800 rounded animate-pulse w-2/3"></div>
        <div class="h-4 bg-gray-100 dark:bg-gray-800 rounded animate-pulse w-1/2"></div>

<!-- L95-98 — Skeleton del card SMD -->

    <div class="flex flex-col gap-2">
```

El sistema tiene `x-admin::shimmer.*` pero ninguno es exactamente para listas de key-value. La solución más limpia es extraer un partial de shimmer reutilizable o simplemente estandarizar las clases. El patrón `animate-pulse` es correcto; el problema es que no está encapsulado. Ver `05.componentes-reutilizables.frontend.md`.

#### C. Badges de estado — clases condicionales inline

El sistema Krayin no tiene un componente `x-admin::badge`. Los badges de seguro se construyen con `:class` condicional:

```html
<!-- L20-30 — Badge seguro (smd-insurance.blade.php) -->
<span
    class="text-xs px-2.5 py-1 rounded-full font-medium"
    :class="{
        'bg-green-100 text-green-700 dark:bg-green-900/30 dark:text-green-400': insurance.status === 'VIGENTE',
        'bg-yellow-100 text-yellow-700 dark:bg-yellow-900/30 dark:text-yellow-400': insurance.status === 'EN_MORA',
        'bg-red-100 text-red-700 dark:bg-red-900/30 dark:text-red-400': insurance.status === 'NO_ENCONTRADO',
        'bg-gray-100 text-gray-500 dark:bg-gray-800 dark:text-gray-400': !insurance.status,
    }"
>
```

```html
<!-- L85-89 — Badge SMD (smd-insurance.blade.php) -->
<span
    class="text-xs px-2.5 py-1 rounded-full font-medium"
    :class="smd.linked
        ? 'bg-green-100 text-green-700 dark:bg-green-900/30 dark:text-green-400'
        : 'bg-gray-100 text-gray-500 dark:bg-gray-800 dark:text-gray-400'"
>
```

```html
<!-- view.blade.php L93-107 — Badges SMD (Blade puro) -->
<span class="inline-flex items-center gap-1 px-2 py-0.5 rounded-full text-xs font-medium bg-green-100 text-green-800">
    Sincronizado
</span>
<span class="inline-flex items-center gap-1 px-2 py-0.5 rounded-full text-xs font-medium bg-yellow-100 text-yellow-800">
    No sincronizado
</span>
```

Hay 3 implementaciones distintas del mismo concepto "badge de estado" en el mismo flujo de usuario. Las clases `py-0.5` vs `py-1` y `text-green-800` vs `text-green-700` crean inconsistencia visual sutil.

**Propuesta — helper method en el componente Vue**:

```javascript
// Añadir a methods de v-smd-insurance-tab
insuranceStatusBadgeClass(status) {
    const map = {
        'VIGENTE':       'bg-green-100  text-green-700  dark:bg-green-900/30  dark:text-green-400',
        'EN_MORA':       'bg-yellow-100 text-yellow-700 dark:bg-yellow-900/30 dark:text-yellow-400',
        'NO_ENCONTRADO': 'bg-red-100    text-red-700    dark:bg-red-900/30    dark:text-red-400',
    };
    return map[status] || 'bg-gray-100 text-gray-500 dark:bg-gray-800 dark:text-gray-400';
},
```

Y en el template:
```html
<span class="text-xs px-2.5 py-1 rounded-full font-medium" :class="insuranceStatusBadgeClass(insurance.status)">
    @{{ insurance.status || 'Sin verificar' }}
</span>
```

Este método ya existe parcialmente para los badges de verificación rápida en el modal de cita (`insuranceBadgeClass()` en doctor-day-calendar, L511). Se propone unificar en una función compartida — ver `05.componentes-reutilizables.frontend.md`.

#### E. Botón "Vincular" en resultados de búsqueda (L186-192)

La clase `rounded primary-button text-white` combina `primary-button` (que ya incluye `rounded`) con `rounded` explícito. `text-white` es redundante si `primary-button` ya incluye el color de texto. Sin consecuencias visuales graves, pero es ruido.


El uso de emojis en UI es inconsistente con el sistema que usa íconos de fuente (`icon-*`). Reemplazar por `<span class="icon-search text-sm"></span>` si existe, o eliminar el ícono.

## Diagnóstico de view.blade.php — v-smd-sync

`view.blade.php` L166-210 define `v-smd-sync` como componente Vue inline con template string. Este componente:

1. Solo muestra el botón "Sincronizar con SMD" si `!smdId` (L178-184).
2. Usa `bg-blue-600 hover:bg-blue-700 text-white` (L182) — fuera del sistema.

**Y en `smd-insurance.blade.php`** ya existe la misma funcionalidad en `syncSmd()` (L320-331) dentro del tab "Seguro & SMD".

El panel lateral (`view.blade.php`) muestra el estado de SMD dos veces:
- Badge Blade (L92-108): renderizado server-side, solo se actualiza al recargar.
- `v-smd-sync` (L110-116): botón Vue que sincroniza y actualiza `smdId` reactivamente.

El tab "Seguro & SMD" ya tiene una interfaz completa y reactiva para todo esto. La duplicación confunde al usuario (dos lugares para sincronizar) y al desarrollador.

**Propuesta**: Eliminar `v-smd-sync` del panel lateral y simplificar el badge Blade a solo mostrar el estado actual (sin botón de acción en el panel lateral). La acción de sincronización vive exclusivamente en el tab.

## Diagnóstico de insurance-verify.blade.php — confirm() nativo

`insurance-verify.blade.php` L210:

```javascript
if (!confirm('¿Estás seguro de que deseas borrar los datos guardados de esta verificación? Esto forzará una nueva consulta a la aseguradora.')) {
    return;
}
```

`window.confirm()` bloquea el thread de JS, no respeta el tema dark/light, y muchos navegadores empresariales lo deshabilitan. 

**Propuesta**: Usar `x-admin::modal.confirm` o un modal inline pequeño:

```javascript
// Opción simple — añadir un ref de modal de confirmación al componente
clearCache() {
    this.$refs.clearCacheConfirmModal.open();
},

confirmClearCache() {
    this.$refs.clearCacheConfirmModal.close();
    this.$axios.post("{{ route(...) }}")
        .then(...)
        .catch(...);
}
```

```html
<x-admin::modal ref="clearCacheConfirmModal" size="normal">
    <x-slot:header>
        <p class="font-semibold dark:text-white">¿Borrar caché de verificación?</p>
    </x-slot>
    <x-slot:content>
        <p class="text-sm text-gray-600 dark:text-gray-400">
            Esto forzará una nueva consulta a la aseguradora en la próxima verificación.
        </p>
    </x-slot>
    <x-slot:footer>
        <button class="secondary-button" @click="$refs.clearCacheConfirmModal.close()">Cancelar</button>
        <button class="danger-button" @click="confirmClearCache">Borrar caché</button>
    </x-slot>
</x-admin::modal>
```
