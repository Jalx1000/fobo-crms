## Diagnóstico del estado actual

### Estructura actual

```

```

### Problemas identificados

**1. z-index de 99999 (hardcoded inline)**  
L894: `style="position:fixed;top:0;left:0;width:100vw;height:100vh;z-index:99999;..."`  
El sistema usa `z-[10003]` para modales. El 99999 garantiza que esté encima de todo pero es frágil y no coordinado con el sistema.

**2. Sin trampa de foco (focus trap)**  
`x-admin::modal` implementa `overflow-hidden` en body y transiciones CSS. El div manual no hace ninguna gestión de foco — Tab navega fuera del modal.

**3. Sin animación de entrada/salida**  
El sistema tiene transiciones `modal-overlay` y `modal-content`. El div manual aparece/desaparece sin transición.

**4. Sin cierre con Escape**  
No hay `@keydown.escape` en el componente padre. `x-admin::modal` tampoco lo implementa nativamente, pero al menos el patrón es consistente.

**5. Clases duplicadas en header/footer manual**  
```html
<!-- Header manual (L900) -->
<div class="flex items-center justify-between px-6 py-4 border-b dark:border-gray-700 flex-shrink-0">

<!-- Footer manual (L1040) -->
<div class="flex justify-between items-center px-6 py-4 border-t dark:border-gray-700 flex-shrink-0">
```
Estas clases son una reimplementación del header/footer de `x-admin::modal` que usa `px-4 py-3` y `px-4 py-2.5`. No son idénticos — hay discrepancia en padding.

**6. Spinner ad-hoc en 3 lugares del sub-modal**  
- L924: `class="animate-spin inline-block w-3 h-3 border-2 border-gray-400 border-t-transparent rounded-full"` (botón Buscar SMD)
- L1013: mismo patrón (botón Verificar cobertura)
- L1054: mismo patrón con `border-white` (botón Crear paciente)

**7. Por qué se usó Teleport**  
El sub-modal se abre desde dentro del slot `content` de `x-admin::modal` (appointmentModal). El modal padre tiene `overflow-hidden` en su contenedor, lo que cortaría el contenido de un modal hijo. El `Teleport to="body"` resuelve esto montando el DOM fuera del árbol del modal padre.

## Propuesta de Refactor

### Opción A: Teleport + x-admin::modal (recomendada)

`x-admin::modal` es un componente Vue (`v-modal`) que se renderiza con `<transition>` y tiene posición `fixed` propia. Si lo montamos dentro del `<Teleport>`, el DOM termina igualmente en `<body>` y la jerarquía z-index del sistema funciona correctamente.

```html
<!-- PROPUESTA — reemplazar el bloque L891-1061 -->

<Teleport to="body">
    <x-admin::modal ref="newPatientModal" size="medium">

        <x-slot:header>
            <p class="text-base font-semibold dark:text-white">Nuevo paciente</p>
        </x-slot>

        <x-slot:content>
            <div class="flex flex-col gap-4 max-h-[70vh] overflow-y-auto">

                {{-- Buscar en SMD --}}
                <div class="bg-gray-50 dark:bg-gray-800 rounded-lg p-3 flex flex-col gap-2">
                    <div class="text-xs font-medium text-gray-500 dark:text-gray-400">
                        Buscar paciente en SMD
                    </div>
                    <div class="flex gap-2">
                        <input
                            type="text"
                            class="flex min-h-[39px] flex-1 rounded-md border px-3 py-2 text-sm text-gray-600 transition-all hover:border-gray-400 dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300"
                            v-model="newPatient.smdQuery"
                            placeholder="Nombre o CI..."
                            @keyup.enter="searchSmd"
                        />
                        <button
                            type="button"
                            class="secondary-button flex items-center gap-1 whitespace-nowrap"
                            @click="searchSmd"
                            :disabled="newPatient.smdSearching"
                        >
                            <x-admin::spinner v-if="newPatient.smdSearching" class="w-4 h-4" />
                            <span v-else>Buscar</span>
                        </button>
                    </div>
                    {{-- resultado SMD omitido por brevedad --}}
                </div>

                {{-- Campos del formulario ... --}}
                {{-- (igual que ahora pero con clases canónicas) --}}

            </div>
        </x-slot>

        <x-slot:footer>
            <button type="button" class="secondary-button" @click="$refs.newPatientModal.close()">
                Cancelar
            </button>
            <button
                type="button"
                class="primary-button"
                @click="saveNewPatient"
                :disabled="newPatient.saving || !newPatient.name.trim()"
            >
                <x-admin::spinner v-if="newPatient.saving" class="w-4 h-4" />
                <span v-else>Crear paciente</span>
            </button>
        </x-slot>

    </x-admin::modal>
</Teleport>
```

**Cambios en JavaScript** — reemplazar `newPatient.open = true/false` por:

```javascript
// Abrir:
this.$nextTick(() => this.$refs.newPatientModal.open());

// Cerrar:
closeNewPatientModal() {
    this.$refs.newPatientModal.close();
    this.resetNewPatient();
},
```

**Ventaja**: Gana animaciones, gestión de body overflow, patrón consistente.  
**Riesgo bajo**: `x-admin::modal` tiene `z-[10003]`; como está en Teleport (DOM en body), no hay problema de clipping.

### Opción B: Mantener Teleport + solo limpiar clases

Si por algún motivo no se quiere usar `x-admin::modal` (ej. necesidad de scroll interno muy personalizado), como mínimo:

1. Unificar padding de header/footer con los estándares del sistema (`px-4 py-3`).
2. Reemplazar 3 spinners ad-hoc por `<x-admin::spinner>`.
3. Cambiar botones custom a `primary-button` / `secondary-button`.
4. Añadir `@keydown.escape.window="closeNewPatientModal"` en el `<div>` raíz del modal.

## Consideración de z-index

| Capa | z-index |
|------|---------|
| Layout sidebar | ~100 |
| Dropdown del sistema | ~1000 |
| `x-admin::modal` overlay | z-[10002] |
| `x-admin::modal` panel | z-[10003] |
| Sub-modal actual (hardcoded) | 99999 |
| Sub-modal propuesto (Teleport + x-admin::modal) | z-[10003] |

Con la Opción A, el sub-modal y el modal padre comparten el mismo z-index del sistema. Dado que el sub-modal se renderiza después en el DOM (Teleport lo pone al final de `<body>`), queda visualmente encima del modal padre sin necesitar un z-index mayor.
