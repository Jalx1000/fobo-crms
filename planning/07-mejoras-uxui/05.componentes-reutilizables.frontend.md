## 1. Campo de verificación de seguro médico

### Problema

El bloque "CI del paciente + tipo de seguro + botón verificar + badge resultado" aparece en **3 lugares** con variaciones de clases CSS:

| Lugar | Archivo | Líneas | Clase input |
|-------|---------|--------|-------------|
| Modal "Añadir cita" | `doctor-day-calendar.blade.php` | 478-516 | `rounded border px-2 py-1.5 text-sm dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300` |
| Sub-modal "Nuevo paciente" | `doctor-day-calendar.blade.php` | 992-1030 | `rounded border px-3 py-2 text-sm w-full dark:border-gray-700 dark:bg-gray-800 dark:text-gray-200` |
| Card "Seguro médico" (tab SMD) | `smd-insurance.blade.php` | todo el card | `flex-1 rounded border px-3 py-1.5 text-sm dark:border-gray-700 dark:bg-gray-800 dark:text-gray-200` |

Tres variantes de clase para el mismo tipo de input. Cada una difiere en `px-2` vs `px-3`, `py-1.5` vs `py-2`, `w-full` vs ausente.

La función `insuranceBadgeClass()` también está duplicada:
- En `doctor-day-calendar.blade.php` como método del componente principal (usado en L512 y L1026).
- La lógica equivalente en `smd-insurance.blade.php` está inlined en el `:class` condicional (L22-27).

### Propuesta — Partial Blade + mixin de función badge

**Opción A: Partial Blade para el bloque HTML** (recomendada para el tab SMD)

El card completo de seguro en `smd-insurance.blade.php` es específico de ese contexto (tiene lógica de carga async, estado persistente, etc.). No tiene sentido extraerlo como partial Blade.

Lo que sí tiene sentido extraer es el **bloque de verificación rápida** (CI + seguro + botón + badge) que aparece en los dos modales del calendario.

Crear: `packages/Webkul/Admin/src/Resources/views/components/insurance/quick-verify-fields.blade.php`

## 2. Función `insuranceBadgeClass` compartida

### Problema

La misma lógica de mapeo de estado-de-seguro a clases de badge existe en dos sitios:

1. `doctor-day-calendar.blade.php` — método `insuranceBadgeClass(badge)` en el componente Vue.
2. `smd-insurance.blade.php` — lógica inline en `:class` condicional.

### Propuesta

Definir la función una vez como utilidad global de Vue en el archivo `app.js` del Admin package:

```javascript
// packages/Webkul/Admin/src/Resources/assets/js/app.js
// Añadir como mixin global o helper en el objeto app

app.config.globalProperties.$insuranceBadgeClass = function(badge) {
    const map = {
        'success': 'bg-green-100 text-green-700 dark:bg-green-900/30 dark:text-green-400',
        'warning': 'bg-yellow-100 text-yellow-700 dark:bg-yellow-900/30 dark:text-yellow-400',
        'error':   'bg-red-100 text-red-700 dark:bg-red-900/30 dark:text-red-400',
    };
    return map[badge] || 'bg-gray-100 text-gray-500 dark:bg-gray-800 dark:text-gray-400';
};

// Para badges de estado SMD/seguro específico:
app.config.globalProperties.$insuranceStatusClass = function(status) {
    const map = {
        'VIGENTE':       'bg-green-100 text-green-700 dark:bg-green-900/30 dark:text-green-400',
        'EN_MORA':       'bg-yellow-100 text-yellow-700 dark:bg-yellow-900/30 dark:text-yellow-400',
        'NO_ENCONTRADO': 'bg-red-100 text-red-700 dark:bg-red-900/30 dark:text-red-400',
    };
    return map[status] || 'bg-gray-100 text-gray-500 dark:bg-gray-800 dark:text-gray-400';
};
```

Uso en templates:
```html
:class="$insuranceStatusClass(insurance.status)"
:class="$insuranceBadgeClass(insurance.result.badge)"
```

## 4. Bloque "estado en panel lateral" de SMD

### Problema

El estado de SMD aparece en 3 formas distintas:

1. **Badge Blade server-side** en `view.blade.php` L92-108 — solo visible al cargar la página.
2. **Componente Vue `v-smd-sync`** en `view.blade.php` L110-116 — reactivo, muestra botón si no está vinculado.
3. **Tab completo `v-smd-insurance-tab`** — card completo con toda la gestión.

## 5. Clase CSS canónica para inputs en contexto Vue

### Problema

Hay 3 variantes de clase para inputs dentro de templates Vue:

| Variante | Lugares |
|----------|---------|
| `rounded border px-2 py-2 text-sm dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300` | appointmentModal (3x), timeOffModal (3x), recurringModal (2x) |
| `rounded border px-3 py-2 text-sm w-full dark:border-gray-700 dark:bg-gray-800 dark:text-gray-200` | newPatient modal (5x) |
| `flex-1 rounded border px-3 py-1.5 text-sm dark:border-gray-700 dark:bg-gray-800 dark:text-gray-200` | smd-insurance (2x) |

La clase canónica del sistema (del componente `form/control-group/control.blade.php`) es:
```
flex min-h-[39px] w-full rounded-md border px-3 py-2 text-sm text-gray-600 transition-all hover:border-gray-400 dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300
```

### Propuesta — CSS custom en el Admin package

Definir una clase utilitaria en `packages/Webkul/Admin/src/Resources/assets/css/app.css`:

```css
/* Clase utilitaria para inputs en templates Vue (equivalente a form.control-group.control) */
.krayin-input {
    @apply flex min-h-[39px] w-full rounded-md border px-3 py-2 text-sm text-gray-600 transition-all 
           hover:border-gray-400 
           dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300;
}
```

Uso: `class="krayin-input"` en lugar de la cadena larga. Esto garantiza que todos los inputs custom sigan el mismo estilo que el sistema y se actualicen automáticamente si el Admin package cambia su CSS base.
