# Sistema de Componentes Krayin — Inventario y Uso

## Componentes `x-admin::*` disponibles

Todos viven en `packages/Webkul/Admin/src/Resources/views/components/`.

| Componente | Archivo | Descripción | Estado de uso |
|------------|---------|-------------|---------------|
| `x-admin::button` | `button/index.blade.php` | Botón Vue con prop `loading` (muestra spinner automáticamente), `title`, `buttonClass` | **Nunca usado** en vistas custom. Se reinventa spinner manual en su lugar. |
| `x-admin::modal` | `modal/index.blade.php` | Modal Vue con slots `header`, `content`, `footer`. Overlay animado, z-index `10002/10003`, métodos `open()`/`close()`/`toggle()` vía ref. Soporta `position` y `size`. | Usado correctamente en `doctor-day-calendar.blade.php` para appointmentModal, groupModal, etc. **No** usado en el sub-modal "Nuevo paciente". |
| `x-admin::spinner` | `spinner/index.blade.php` | SVG animado con `animate-spin`. Acepta `color` y clases via `$attributes`. | Usado en footers de modales del calendario. **No** usado en cards de `smd-insurance.blade.php` ni en "Nuevo paciente". |
| `x-admin::shimmer.*` | `shimmer/` (árbol completo) | Skeleton loaders para datagrid, activities, accordion, tabs, etc. | Usado en `persons/index.blade.php` (datagrid). **No** usado en `smd-insurance.blade.php` donde se construye shimmer manualmente. |
| `x-admin::form` | `form/index.blade.php` | Wrapper de formulario con VeeValidate. | Usado en `create.blade.php` y `edit.blade.php`. |
| `x-admin::form.control-group` | `form/control-group/index.blade.php` | Contenedor de campo con label, control y error. | Usado correctamente en `insurance-verify.blade.php` L43 y L54. **No** usado en los ~25 inputs del calendario ni en `smd-insurance.blade.php`. |
| `x-admin::form.control-group.label` | `form/control-group/label.blade.php` | Label del sistema con soporte `required`. | Usado en `insurance-verify.blade.php`. |
| `x-admin::form.control-group.control` | `form/control-group/control.blade.php` | Input genérico con integración VeeValidate. | Disponible pero no usado en vistas Vue (correcto — en contexto Vue se prefiere `v-model` directo, pero la clase CSS del sistema debería aplicarse). |
| `x-admin::lookup` | `lookup/index.blade.php` | Autocomplete con búsqueda API. Soporta `can-add-new`. | Usado correctamente en el modal de cita para paciente y servicio. |
| `x-admin::accordion` | `accordion/index.blade.php` | Sección colapsable. | No relevante en las vistas auditadas. |
| `x-admin::tabs` | `tabs/index.blade.php` + `tabs/item.blade.php` | Pestañas del sistema. | Disponible; las pestañas de personas usan `x-admin::activities` que internamente tiene sus propias tabs. |
| `x-admin::modal.confirm` | `modal/confirm.blade.php` | Modal de confirmación reutilizable. | **Existe** pero no se usa — se usa `confirm()` nativo del navegador en `insurance-verify.blade.php` L210. |
| `x-admin::dropdown` | `dropdown/index.blade.php` | Dropdown del sistema. | No evaluado en este scope. |
| `x-admin::flat-picker.date` | `flat-picker/date.blade.php` | Date picker con flatpickr. | Disponible. En las vistas custom se usan `<input type="date">` nativos en su lugar. |

### Clases CSS del sistema (no componentes Blade)

Estas clases se aplican directamente en Blade/HTML:

| Clase | Propósito |
|-------|-----------|
| `primary-button` | Botón primario (azul/marca). Ya definida en el CSS del Admin. |
| `secondary-button` | Botón secundario (borde, sin relleno). |
| `danger-button` | Botón destructivo (rojo). |
| `box-shadow` | Sombra estándar para cards/panels. |

## Lo que se está usando mal o no se usa

### 1. `x-admin::button` — ignorado por completo

El componente acepta `:loading="true"` y muestra el spinner automáticamente. Sin embargo, **ninguna** vista custom lo usa. En su lugar se repite este patrón 7+ veces:

```html
<!-- ACTUAL (mal) — en doctor-day-calendar.blade.php línea 1054 -->
<button type="button"
    class="primary-button text-white px-5 py-2 rounded-lg text-sm font-medium disabled:opacity-50 flex items-center gap-2"
    @click="saveNewPatient"
    :disabled="newPatient.saving || !newPatient.name.trim()"
>
    <span v-if="newPatient.saving"
        class="animate-spin inline-block w-3.5 h-3.5 border-2 border-white border-t-transparent rounded-full">
    </span>
    Crear paciente
</button>
```

```html
<!-- CORRECTO — usando x-admin::spinner dentro del patrón del sistema -->
<button type="button"
    class="primary-button"
    @click="saveNewPatient"
    :disabled="newPatient.saving || !newPatient.name.trim()"
>
    <x-admin::spinner v-if="newPatient.saving" class="w-4 h-4" />
    <span v-else>Crear paciente</span>
</button>
```

Nota: `x-admin::button` está pensado para botones Blade server-side. Para botones Vue con `v-if`/`:disabled` dinámicos, el patrón correcto es usar `primary-button` con `<x-admin::spinner>` anidado, como ya se hace en los footers de los modales del calendario (L525-529). El problema es que este patrón correcto no se aplica de forma consistente.

### 2. `x-admin::form.control-group` — ignorado en vistas Vue

En `insurance-verify.blade.php` (Blade puro) se usa correctamente. En las vistas Vue del calendario y smd-insurance se usan inputs directos:

```html
<!-- ACTUAL (inconsistente) — smd-insurance.blade.php línea 157 -->
<input
    type="text"
    class="flex-1 rounded border px-3 py-1.5 text-sm dark:border-gray-700 dark:bg-gray-800 dark:text-gray-200"
    v-model="smd.searchTerm"
/>
```

La clase `rounded border px-3 py-1.5 text-sm dark:border-gray-700 dark:bg-gray-800 dark:text-gray-200` es una aproximación manual de los estilos del sistema. El componente `x-admin::form.control-group.control` tiene la clase canónica `flex min-h-[39px] w-full rounded-md border px-3 py-2 text-sm text-gray-600 transition-all hover:border-gray-400 dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300`. Las diferencias son pequeñas pero acumulan inconsistencia visual.

En contexto Vue, dado que no se puede usar VeeValidate en templates string, la solución es extraer la clase canónica del sistema a una constante CSS o aplicarla directamente como se muestra en `insurance-verify.blade.php` L48.

### 3. `x-admin::shimmer` — ignorado en smd-insurance

```html
<!-- ACTUAL (ad-hoc) — smd-insurance.blade.php líneas 34-37 -->
<template v-if="insurance.loading">
    <div class="flex flex-col gap-2">
        <div class="h-4 bg-gray-100 dark:bg-gray-800 rounded animate-pulse w-2/3"></div>
        <div class="h-4 bg-gray-100 dark:bg-gray-800 rounded animate-pulse w-1/2"></div>
    </div>
</template>
```

No existe un shimmer exacto para este caso, pero el patrón de `animate-pulse` se puede extraer a un componente Blade propio o usar `x-admin::shimmer.common.address` como referencia de estructura.

### 4. `x-admin::modal.confirm` — ignorado

Existe en `modal/confirm.blade.php` pero `insurance-verify.blade.php` L210 usa `window.confirm()` nativo para confirmar borrado de caché. Debe migrarse.

### 5. `x-admin::flat-picker.date` — disponible pero no usado

Los modales de "Turnos Recurrentes" y "Días Libres" usan `<input type="date">` nativo. El componente flatpickr del sistema ofrece mejor UX (calendario visual, formato localizado).
