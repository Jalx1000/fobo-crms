### Problemas específicos

**1. Selects con clase Tailwind manual (L395-460)**

Se repite 3 veces esta clase en selects del formulario:
```html
class="rounded border px-2 py-2 text-sm dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300"
```

La clase canónica del sistema (de `insurance-verify.blade.php` L56-58) es:
```html
class="flex min-h-[39px] w-full rounded-md border px-3 py-2 text-sm text-gray-600 transition-all hover:border-gray-400 dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300"
```

Diferencias: falta `min-h-[39px]`, `w-full`, `rounded-md`, `transition-all`, `hover:border-gray-400`, `text-gray-600`. Visualmente los selects son ligeramente más cortos y sin efecto hover.

**2. Textarea "Motivo de consulta" sin resize control (L465-471)**

```html
<textarea
    rows="3"
    class="w-full rounded border px-2 py-2 text-sm dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300"
    v-model="appointmentForm.reason"
    placeholder="Motivo de consulta"
></textarea>
```

No tiene `resize-none` ni el sistema de control de grupo. El usuario puede arrastrar y romper el layout del modal.

**3. Labels como `<div class="text-xs text-gray-600 dark:text-gray-300">` (L379, 393, 404, etc.)**

Se usan `<div>` en lugar de `<label>` (sin atributo `for`). Esto rompe la accesibilidad: el click en el label no enfoca el campo.

**4. Comentario de debug en el código (L448)**

```html
<!-- aaaaaaaaaaaaaaaaaaaaaaaa -->
```
Debe eliminarse.

**5. Typo: "Seguro medico" sin tilde (L476)**

```html
<div class="text-xs font-semibold text-gray-600 dark:text-gray-300 mb-2">Seguro medico</div>
```
Debe ser "Seguro médico".

**6. Sección seguro dentro del modal de cita (L475-516)**

La sección de seguro médico solo aparece `v-if="appointmentForm.person.id"` — bien pensado. Pero los inputs usan clases manuales distintas a las del smd-insurance.blade.php:

```html
<!-- Modal cita L480 -->
class="rounded border px-2 py-1.5 text-sm dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300"

<!-- smd-insurance.blade.php L157 -->
class="flex-1 rounded border px-3 py-1.5 text-sm dark:border-gray-700 dark:bg-gray-800 dark:text-gray-200"
```

Hay 3 variantes distintas de la misma clase de input en el proyecto. Ver `05.componentes-reutilizables.frontend.md` para la propuesta de extracción.

## Diagnóstico de modales secundarios

### Modal "Turnos Recurrentes" (L568-633)

**Problema principal — inputs `type="date"` nativos (L580, L584)**:
```html
<input type="date" class="rounded border px-2 py-2 text-sm dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300" v-model="recurringForm.start_date" />
```

El sistema tiene `x-admin::flat-picker.date` basado en flatpickr. Sin embargo, en contexto Vue dinámico, flatpickr requiere inicialización manual. La solución más pragmática es usar la clase canónica del sistema en el input nativo y dejar la migración a flatpickr como mejora opcional posterior.

**Checkboxes de días de la semana (L591-594)**:
```html
<input type="checkbox" :value="idx+1" v-model="recurringForm.days" class="hidden" />
```
El checkbox está oculto y el label hace de toggle visual. Patrón válido, pero el label `.flex.cursor-pointer.px-3.py-2.border.rounded` no sigue el sistema. Aceptable como componente custom de este modal.

### Modal "Días Libres" (L636-716)

**Botón Guardar con color hardcoded (L710)**:
```html
<button type="button" class="primary-button bg-black hover:bg-gray-800 text-white" @click="saveTimeOff" ...>
```
`bg-black hover:bg-gray-800` sobreescribe el color de `primary-button`. Sin razón clara para que este botón sea negro mientras todos los demás son del color del sistema. Debe eliminarse el override.

**Checkboxes sin sistema de control (L681, L692)**:
```html
<input type="checkbox" id="to-repeat" v-model="timeOffForm.repeat" class="rounded border-gray-300 text-blue-600 focus:ring-blue-500" />
<label for="to-repeat" ...>Repetir</label>
```
Patrón correcto (usa `for`/`id`). La clase `text-blue-600 focus:ring-blue-500` es Tailwind directo, pero es aceptable para checkboxes.

## Propuesta de mejoras concretas

### Fix 1 — Clase canónica para selects y textareas en el modal

Reemplazar la clase manual repetida por la clase canónica del sistema en todos los selects del modal (líneas 396-401, 420-430, 453-458):

```html
<!-- ANTES -->
<select
    class="rounded border px-2 py-2 text-sm dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300"
    v-model="appointmentForm.doctor_id"
>

<!-- DESPUÉS -->
<select
    class="flex min-h-[39px] w-full rounded-md border px-3 py-2 text-sm text-gray-600 transition-all hover:border-gray-400 dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300"
    v-model="appointmentForm.doctor_id"
>
```

### Fix 2 — Labels con elemento `<label>` semántico

```html
<!-- ANTES (L393) -->
<div class="text-xs text-gray-600 dark:text-gray-300">Doctor</div>
<select ...>

<!-- DESPUÉS -->
<label for="appointment-doctor" class="text-xs font-medium text-gray-600 dark:text-gray-300">Doctor</label>
<select id="appointment-doctor" ...>
```

### Fix 3 — Textarea con resize-none

```html
<!-- ANTES -->
<textarea rows="3" class="w-full rounded border px-2 py-2 text-sm ..." ...></textarea>

<!-- DESPUÉS -->
<textarea
    rows="3"
    class="flex w-full rounded-md border px-3 py-2 text-sm text-gray-600 transition-all hover:border-gray-400 dark:border-gray-800 dark:bg-gray-900 dark:text-gray-300 resize-none"
    v-model="appointmentForm.reason"
    placeholder="Motivo de consulta"
></textarea>
```

### Fix 4 — Eliminar comentario debug y corregir typo

```
L448: eliminar <!-- aaaaaaaaaaaaaaaaaaaaaaaa -->
L476: "Seguro medico" → "Seguro médico"
```

### Fix 5 — Botón Guardar en timeOffModal

```html
<!-- ANTES (L710) -->
<button type="button" class="primary-button bg-black hover:bg-gray-800 text-white" ...>

<!-- DESPUÉS -->
<button type="button" class="primary-button" ...>
```

### Fix 6 — Botón de acción "Seguro" en panel de actividades

`insurance-verify.blade.php` L11-16 tiene un botón de acción custom que no sigue el patrón de los demás botones de actividad del sistema (`x-admin::activities.actions.*`). El patrón de los otros botones usa un tamaño fijo de 74x84px con icono y texto. El botón de seguro tiene los mismos dimensiones pero usa `bg-orange-200` en lugar del background estándar.

Verificar si existe un `bg-orange-200` en los otros action buttons del sistema (mail, note, file, activity). Si no, unificar al color estándar o justificar la diferencia de color.
