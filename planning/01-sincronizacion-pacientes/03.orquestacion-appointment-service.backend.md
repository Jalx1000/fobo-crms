# Tarea 1.3 — Sincronización de paciente en `AppointmentService`

**Agente asignado:** `backend`
**Fase:** 01 — Sincronización de Pacientes
**Complejidad:** Alta
**Tiempo estimado:** 4h
**Dependencias:** Tarea 1.1 (columna `smd_patient_id`), Tarea 1.2 (métodos patient API)

## Objetivo

Antes de crear el evento en ShareMeData (`createEvent`), asegurar que el paciente existe en SMD y que el CRM tiene su `_id` SMD guardado localmente. Enriquecer el payload del evento con los datos reales del paciente.

## Archivo a modificar

```
packages/Webkul/Admin/src/Services/AppointmentService.php
```

## Dónde insertar el código

En el método `process()`, insertar el nuevo paso **entre el paso 4 (verificar disponibilidad) y el paso 5 (createEvent)**:

```
Paso 4: Verificar disponibilidad en SMD ✅ (existente)
Paso 4.5: ⬅️ NUEVO — Sincronizar paciente con SMD
Paso 5: Crear evento en SMD (existente, pero enriquecido)
Paso 6: Crear registros locales (existente)
```

## Implementación

### Lógica del paso 4.5

```php
// ── 4.5 Sincronizar paciente con SMD ────────────────────────────────────────
$smdPatientId = $person->smd_patient_id ?? null;

if (! $smdPatientId) {
    // Intentar encontrar el paciente en SMD por teléfono
    $smdPatients = $this->shareMeDataService->searchPatient($personPhone);

    if (! empty($smdPatients)) {
        // Existe en SMD — guardar su _id localmente
        $smdPatientId = $smdPatients[0]['_id'] ?? null;

        if ($smdPatientId) {
            $this->personRepository->update(['smd_patient_id' => $smdPatientId], $person->id);
            Log::info('[Appointment] smd_patient_id sincronizado desde búsqueda', [
                'person_id'      => $person->id,
                'smd_patient_id' => $smdPatientId,
            ]);
        }
    } else {
        // No existe en SMD — crear el paciente
        $nameParts = explode(' ', trim($person->name ?? 'Paciente'));
        $firstName = $nameParts[0];
        $lastName  = count($nameParts) > 1 ? implode(' ', array_slice($nameParts, 1)) : 'Externo';

        $createResult = $this->shareMeDataService->createPatient([
            'first_name' => $firstName,
            'last_name'  => $lastName,
            'phone'      => $personPhone,
            'email'      => $this->resolvePersonEmail($person),
        ]);

        if ($createResult['success']) {
            $smdPatientId = $createResult['data']['_id'] ?? null;

            if ($smdPatientId) {
                $this->personRepository->update(['smd_patient_id' => $smdPatientId], $person->id);
                Log::info('[Appointment] Paciente creado en SMD', [
                    'person_id'      => $person->id,
                    'smd_patient_id' => $smdPatientId,
                ]);
            }
        } elseif ($createResult['duplicate'] ?? false) {
            // Duplicado — buscar por teléfono para recuperar el _id
            $retry = $this->shareMeDataService->searchPatient($personPhone);
            $smdPatientId = $retry[0]['_id'] ?? null;

            if ($smdPatientId) {
                $this->personRepository->update(['smd_patient_id' => $smdPatientId], $person->id);
            }
        }
        // Si sigue sin ID, continuar sin él — no bloquear la cita
    }
}
```

### Método helper privado a agregar

```php
private function resolvePersonEmail(object $person): ?string
{
    if (empty($person->emails)) {
        return null;
    }
    $emails = is_array($person->emails) ? $person->emails : json_decode($person->emails, true);
    return $emails[0]['value'] ?? null;
}
```

## Criterios de aceptación

- [ ] Al crear una cita para un paciente sin `smd_patient_id`, se busca primero en SMD por teléfono
- [ ] Si el paciente existe en SMD, su `_id` se guarda en `persons.smd_patient_id`
- [ ] Si no existe, se crea en SMD y se guarda el `_id`
- [ ] Si SMD retorna duplicado (400), se hace una búsqueda de recuperación
- [ ] Si todo falla (SMD no responde), la cita se crea de todas formas sin bloquear
- [ ] El `personID` en el payload de `createEvent` usa el `smd_patient_id` si está disponible
- [ ] No se logguean datos de CI o emails completos en nivel warning+

## Riesgo a tener en cuenta

> Si SMD rechaza el `createEvent` porque el `personID` no coincide con un paciente registrado, el flujo fallará con 422. Validar este comportamiento en el ambiente gamma antes de activar en producción.
