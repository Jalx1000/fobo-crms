# Tarea 3.1 — Diseño de arquitectura: ingesta de citas desde Dropbox

**Agente asignado:** `backend` + `arquitecto`
**Fase:** 03 — Sincronización Dropbox
**Complejidad:** Alta (decisión de arquitectura)
**Tiempo estimado:** 2h
**Dependencias:** Cuenta Dropbox activa y compartida por SMD ⚠️ (acción externa)

---

## Objetivo

Definir cómo el CRM va a leer los archivos JSON que SMD escribe en Dropbox cuando una cita es confirmada directamente en la interfaz de SMD (sin pasar por el CRM).

## Contexto del mecanismo Dropbox (del PDF)

SMD escribe un archivo JSON por evento confirmado en una carpeta Dropbox compartida:

```
Estructura de carpetas SMD:
/appointments/
  /2026-05-19/
    evento-abc123.json
    evento-def456.json
  /2026-05-20/
    ...
```

**Schema del archivo JSON (del PDF):**
```json
{
  "_id": "evt-abc123",
  "summary": "CONSULTA: Javier Pérez",
  "startDate": "2026-05-19T10:00:00-04:00",
  "endDate": "2026-05-19T11:00:00-04:00",
  "owner": {
    "_id": "69bd9a9b7549b10008e0acfa",
    "name": "Dr. Eloy",
    "lastName": "Monteroca"
  },
  "attendances": [
    {
      "patient": {
        "_id": "pat-xyz",
        "name": "Javier",
        "lastName": "Pérez",
        "phone": "77788990"
      }
    }
  ]
}
```

## Opciones de arquitectura

### Opción A — Pull via scheduler (RECOMENDADA para MVP)

```
Laravel Scheduler (cada 5 min)
    ↓
Artisan Command: smd:sync-dropbox
    ↓
Dropbox API v2 (listar archivos nuevos)
    ↓
Descargar y parsear JSON
    ↓
IncomingAppointmentService::processIncoming()
    ↓
Lead + Activity + Person en CRM
```

**Pros:** Simple, sin infraestructura extra, fácil de debuggear, reintentos automáticos
**Contras:** Latencia de hasta 5 minutos, polling aunque no haya citas nuevas

### Opción B — Push via Dropbox Webhook

```
Dropbox notifica al CRM (POST /api/dropbox/webhook)
    ↓
CRM lee el archivo específico de Dropbox
    ↓
IncomingAppointmentService::processIncoming()
```

**Pros:** Tiempo real, sin polling
**Contras:** Requiere endpoint público + verificación de Dropbox, más complejidad

### Decisión

**Para MVP: Opción A.** Implementar Opción B como mejora posterior si la latencia de 5 minutos es inaceptable para el negocio.

## Pasos previos a iniciar desarrollo (acción humana)

## Dependencias de librería

Usar `Http` de Laravel directamente con la API de Dropbox v2 (sin SDK para no agregar dependencias innecesarias):

```php
// Listar archivos en carpeta
Http::withToken($dropboxToken)
    ->withHeaders(['Content-Type' => 'application/json'])
    ->post('https://api.dropboxapi.com/2/files/list_folder', [
        'path' => '/appointments/' . now()->toDateString(),
    ]);

// Descargar archivo
Http::withToken($dropboxToken)
    ->withHeaders(['Dropbox-API-Arg' => json_encode(['path' => $filePath])])
    ->post('https://content.dropboxapi.com/2/files/download');
```

## Variables de entorno a agregar

```env
DROPBOX_ACCESS_TOKEN=your-dropbox-token
DROPBOX_APPOINTMENTS_FOLDER=/appointments
```

```php
// config/services.php
'dropbox' => [
    'access_token'        => env('DROPBOX_ACCESS_TOKEN'),
    'appointments_folder' => env('DROPBOX_APPOINTMENTS_FOLDER', '/appointments'),
],
```
