# Tarea 3.4 — QA: Flujo Dropbox end-to-end

**Agente asignado:** `qa`
**Fase:** 03 — Sincronización Dropbox
**Complejidad:** Media
**Tiempo estimado:** 2h
**Dependencias:** Tarea 3.2 (comando sync), Tarea 3.3 (IncomingAppointmentService), acceso Dropbox activo

---

## Objetivo

Validar en ambiente gamma que el flujo completo Dropbox funciona: SMD escribe el archivo → el comando lo lee → el CRM crea los registros correctos.

## Prerequisitos

- [ ] Cuenta Dropbox activa y compartida por SMD
- [ ] `DROPBOX_ACCESS_TOKEN` configurado en Easypanel
- [ ] Comando `smd:sync-dropbox` deployado
- [ ] Acceso a `gamma.sharemedata.com` con usuario `staff.odontoking@smd.com`

## Plan de pruebas

### Prueba 1 — Creación de cita en SMD y sincronización

**Pasos:**
1. Ir a `https://gamma.sharemedata.com` y loguearse con `staff.odontoking@smd.com / GammaOdontoking123#`
2. Crear una cita nueva con uno de los 3 doctores de prueba, con fecha de hoy
3. Confirmar la cita en SMD
4. Esperar ~1 minuto para que SMD escriba el archivo en Dropbox
5. Ejecutar: `crm php artisan smd:sync-dropbox --date=$(date +%Y-%m-%d)`
6. Verificar en el CRM que se creó el Lead y la Activity

**Resultado esperado:**
- Un nuevo Lead con el nombre del paciente y la especialidad
- Una Activity tipo `meeting` con las fechas correctas
- Un registro en `smd_synced_events` con el `external_id` del evento

### Prueba 2 — Idempotencia

**Pasos:**
1. Ejecutar el comando dos veces seguidas para la misma fecha
2. Verificar que no se duplicaron el Lead ni la Activity

**Resultado esperado:**
- El segundo run dice `X ya existían` y 0 procesados nuevos

### Prueba 3 — Dry-run

**Pasos:**
1. Ejecutar `crm php artisan smd:sync-dropbox --dry-run`
2. Verificar que lista archivos pero NO crea registros

**Resultado esperado:**
- Output: `[DRY-RUN] /appointments/2026-05-XX/evento-abc.json`
- Cero registros nuevos en `smd_synced_events`

### Prueba 4 — Schema correcto

**Verificar que los datos se mapean correctamente:**

```bash
crm php artisan tinker --execute="
    \$event = DB::table('smd_synced_events')->latest()->first();
    \$activity = Webkul\Activity\Models\Activity::find(\$event->activity_id);
    echo 'schedule_from: '.\$activity->schedule_from.PHP_EOL;
    echo 'doctors: '.\$activity->doctors->pluck('name').PHP_EOL;
    echo 'lead: '.\$activity->leads->first()->title.PHP_EOL;
"
```

### Prueba 5 — Comportamiento ante carpeta vacía

**Pasos:**
1. Ejecutar el comando con una fecha sin citas: `crm php artisan smd:sync-dropbox --date=2020-01-01`

**Resultado esperado:**
- No falla, dice `0 procesados, 0 ya existían, 0 errores`

## Criterios de aceptación

- [ ] Cita creada en SMD aparece en el CRM después de ejecutar el comando
- [ ] Fechas y horarios coinciden correctamente (timezone Bolivia)
- [ ] Doctor correcto asignado a la actividad
- [ ] No se duplican registros en ejecuciones repetidas
- [ ] El comando no falla si la carpeta Dropbox de la fecha está vacía
- [ ] Los logs en `storage/logs/laravel-FECHA.log` no contienen errores por esta operación
