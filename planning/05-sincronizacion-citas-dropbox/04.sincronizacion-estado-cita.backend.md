## Objetivo

Definir cómo el campo `status` del JSON SMD y la bandera `archived: true` se mapean a estados del Lead en el CRM. Implementar la propagación de cambios de estado.

---

## Contexto: estados en el CRM

Los Leads en Krayin tienen dos mecanismos de estado:

1. **`lead_stage_id`** — FK a `lead_stages` (stages del pipeline). Ejemplos típicos: `new`, `contacted`, `in_progress`, `won`, `lost`. Los stages son configurables por el admin del CRM.

2. **`status` (boolean)** — campo en `leads` que indica si el lead está abierto (`null`/`1`) o cerrado (`0`). Al marcar un lead como perdido, `status = 0` y se guarda `lost_reason`.

Los stages concretos dependen de la configuración del pipeline del cliente. No hay valores hardcodeados en código.

---

## Campo `status` en el JSON de SMD ✅ DEFINIDO

Valores confirmados por el usuario (normalizar con `strtolower()` para ser robusto):

| `status` real en SMD | Normalizado | Significado | Acción en CRM |
|----------------------|-------------|-------------|---------------|
| `""` (vacío) | `""` | Sin estado → **tratar como confirmed** | Mover a stage confirmed |
| `"confirmed"` | `"confirmed"` | Cita confirmada | Mover a stage confirmed |
| `"CANCELED"` | `"canceled"` | Cita cancelada | Mover a stage cancelado + tag "Cancelado" |
| `"completed"` | `"completed"` | Cita completada | Mover a stage won/completado |
| `"no-show"` | `"no-show"` | Paciente no se presentó | Mover a stage cancelado + tag "No-show" |

**Nota importante:** El valor real observado en el JSON es `"CANCELED"` (mayúsculas), no `"cancelled"`. El mapper usa `strtolower()` para normalizar.

---

## Bandera `archived: true` ✅ DEFINIDO

**Comportamiento decidido — Opciones A + C combinadas:**
- Mover el Lead al stage de cancelado/perdido
- Agregar tag `"Cancelado"` al Lead
- La Activity NO se elimina (queda como historial)

**Importante:** `archived: true` y `status: "CANCELED"` son mecanismos independientes. Un evento puede tener `archived: false` con `status: "CANCELED"`. Ambos disparan el mismo flujo de cancelación.

## Implementación: `SmdStatusMapper`

Crear un servicio pequeño para mantener la tabla de equivalencias separada de la lógica de procesamiento:

```
packages/Webkul/Admin/src/Services/SmdStatusMapper.php
```

```php
<?php

namespace Webkul\Admin\Services;

class SmdStatusMapper
{
    /**
     * Normaliza el status de SMD (puede venir en cualquier case).
     * Vacío se trata como "confirmed" según decisión de negocio.
     */
    public function normalize(?string $smdStatus): string
    {
        $normalized = strtolower(trim($smdStatus ?? ''));
        // Vacío = confirmed
        return $normalized === '' ? 'confirmed' : $normalized;
    }

    /**
     * Mapea el campo status de SMD a un lead_stage code del CRM.
     * "canceled" y "cancelled" se tratan igual (SMD usa "CANCELED").
     */
    public function toLeadStageCode(?string $smdStatus): ?string
    {
        return match ($this->normalize($smdStatus)) {
            'confirmed'            => config('smd.stage_map.confirmed'),
            'completed'            => config('smd.stage_map.completed'),
            'canceled', 'cancelled'=> config('smd.stage_map.cancelled'),
            'no-show'              => config('smd.stage_map.no_show'),
            default                => null,
        };
    }

    /**
     * Retorna true si el status implica cancelar/cerrar el lead.
     */
    public function isCancelled(?string $smdStatus): bool
    {
        return in_array($this->normalize($smdStatus), ['canceled', 'cancelled', 'no-show']);
    }

    /**
     * Retorna el tag a agregar al Lead según el status.
     */
    public function getTag(?string $smdStatus): ?string
    {
        return match ($this->normalize($smdStatus)) {
            'canceled', 'cancelled' => 'Cancelado',
            'no-show'               => 'No-show',
            default                 => null,
        };
    }
}
```

public function updateDropbox(array $data, object $existing): array
{
    // ... (código de Tarea 5.2)

    return DB::transaction(function () use ($data, $activityId, $leadId) {
        $normalized  = $this->normalizeDropbox($data);
        $stageCode   = $this->statusMapper->toLeadStageCode($normalized['status']);

        // Actualizar Activity
        // ...

        // Propagar cambio de stage si corresponde
        if ($leadId && $stageCode) {
            $stage = DB::table('lead_stages')->where('code', $stageCode)->first();

            if ($stage) {
                $updateData = ['lead_stage_id' => $stage->id];

                if ($this->statusMapper->isLost($normalized['status'])) {
                    $updateData['status']      = 0;
                    $updateData['lost_reason'] = 'Cita '.$normalized['status'].' en SMD';
                    $updateData['closed_at']   = now();
                }

                $this->leadRepository->update($updateData, $leadId);

                Log::info('[IncomingAppointment] Stage de lead actualizado', [
                    'lead_id'    => $leadId,
                    'smd_status' => $normalized['status'],
                    'stage_code' => $stageCode,
                ]);
            } else {
                Log::warning('[IncomingAppointment] Stage code no encontrado en CRM', [
                    'stage_code' => $stageCode,
                ]);
            }
        }

        return ['lead_id' => $leadId, 'activity_id' => $activityId, 'action' => 'updated'];
    });
}

## Flujo `archived: true` (ya en Tarea 5.2, aquí el detalle)

```php
public function cancelDropbox(string $externalId, object $existing): array
{
    return DB::transaction(function () use ($externalId, $existing) {
        $leadId     = $existing->lead_id;
        $activityId = $existing->activity_id;

        if ($leadId) {
            $cancelledStageId = config('smd.cancelled_lead_stage_id');

            $updateData = [
                'lost_reason' => 'Cita cancelada en SMD',
                'closed_at'   => now(),
            ];

            if ($cancelledStageId) {
                $updateData['lead_stage_id'] = $cancelledStageId;
            }

            $this->leadRepository->update($updateData, $leadId);

            // Agregar tag "Cancelado" al Lead (Opciones A+C)
            $cancelTag = \Webkul\Tag\Repositories\TagRepository::firstOrCreate(['name' => 'Cancelado']);
            $lead = $this->leadRepository->find($leadId);
            $lead->tags()->syncWithoutDetaching([$cancelTag->id]);
        }

        // La Activity NO se elimina. Queda como historial.

        Log::info('[IncomingAppointment] Lead cancelado por archived=true en SMD', [
            'external_id' => $externalId,
            'lead_id'     => $leadId,
        ]);

        return ['lead_id' => $leadId, 'activity_id' => $activityId, 'action' => 'cancelled'];
    });
}
```

## Cuándo NO propagar cambios de estado

| Condición | Razón |
|-----------|-------|
| `status` vacío o null | SMD no indica estado definido |
| `status` desconocido (no está en el mapeo) | Evitar regresiones por nuevos valores de SMD no anticipados |
| Lead ya está cerrado (`status = 0`) | No reabrir leads cerrados manualmente por el equipo |
| Lead no existe en `smd_synced_events.lead_id` | Datos inconsistentes, loguear error |
