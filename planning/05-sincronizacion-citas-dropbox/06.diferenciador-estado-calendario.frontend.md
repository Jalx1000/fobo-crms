# Tarea 5.6 — Diferenciador visual de estado de cita en el calendario

**Agente asignado:** `frontend`
**Fase:** 05 — Sincronización de Citas desde Dropbox
**Complejidad:** Media
**Tiempo estimado:** 3h
**Dependencias:** Tarea 5.4 (los stages cancelado/confirmado deben existir en el pipeline)

---

## Objetivo

El calendario de día (`doctor-day-calendar.blade.php`) debe mostrar visualmente el estado de cada cita. Específicamente distinguir entre:

- **Confirmada** — cita activa, estado normal
- **Cancelada** — cita cancelada (stage cancelado o tag "Cancelado")
- **Completada** — cita atendida
- **No-show** — paciente no se presentó

---

## Estado actual

Las citas se renderizan como bloques de color en el calendario. Actualmente todos los bloques usan el mismo estilo independientemente del estado del Lead. El color del bloque se basa en el doctor asignado, no en el estado de la cita.

---

## Diseño propuesto

### Indicadores visuales por estado

| Estado | Color de fondo | Borde | Ícono | Opacity |
|--------|---------------|-------|-------|---------|
| Confirmada | Color del doctor (actual) | Ninguno | — | 100% |
| Cancelada | Gris (`bg-gray-200`) | Borde rojo punteado | ✕ | 70% |
| Completada | Verde claro (`bg-green-100`) | Borde verde | ✓ | 100% |
| No-show | Naranja claro (`bg-orange-100`) | Borde naranja | — | 80% |

### Texto tachado para canceladas

Las citas canceladas muestran el nombre del paciente con `line-through` para reforzar visualmente que está cancelada.

### Implementación en el template Vue

Los bloques de cita en el calendario se renderizan con algo similar a:

```html
<!-- En el template del evento del calendario -->
<div
  class="appointment-block"
  :class="appointmentClasses(ev)"
  ...
>
  <span :class="{ 'line-through opacity-60': isCancelled(ev) }">
    {{ ev.person_name }}
  </span>
  <span v-if="isCancelled(ev)" class="text-red-500 text-xs ml-1">✕</span>
  <span v-if="isCompleted(ev)" class="text-green-600 text-xs ml-1">✓</span>
</div>
```

### Métodos Vue a agregar al componente

```js
isCancelled(ev) {
    // Verificar por stage name/code o por presencia del tag "Cancelado"
    const stageName = (ev.lead_pipeline_stage_name || '').toLowerCase();
    return stageName.includes('cancel') || (ev.tags || []).some(t => t.name === 'Cancelado');
},

isCompleted(ev) {
    const stageName = (ev.lead_pipeline_stage_name || '').toLowerCase();
    return stageName.includes('complet') || stageName.includes('atendi');
},

isNoShow(ev) {
    return (ev.tags || []).some(t => t.name === 'No-show');
},

appointmentClasses(ev) {
    if (this.isCancelled(ev)) return 'bg-gray-100 border-2 border-dashed border-red-300 opacity-70';
    if (this.isCompleted(ev)) return 'bg-green-100 border border-green-400';
    if (this.isNoShow(ev))    return 'bg-orange-100 border border-orange-400 opacity-80';
    return ''; // Estilo normal (color del doctor)
},
```

## Cambios en el backend necesarios

Para que el frontend pueda saber el estado, el endpoint que devuelve las citas del calendario debe incluir:

1. `lead_pipeline_stage_name` — nombre del stage del Lead (ya puede existir)
2. `tags` — array de tags del Lead `[{ id, name }]`

### Verificar en `ActivityController::getForCalendar()` (o equivalente)

El endpoint que devuelve los eventos del calendario (probablemente `GET /admin/activities/calendar`) debe incluir en cada evento:

```php
'lead_pipeline_stage_name' => $activity->lead->pipelineStage->name ?? null,
'tags'                     => $activity->lead->tags->map(fn($t) => ['id' => $t->id, 'name' => $t->name]),
```

Si el endpoint no incluye estos campos, agregar la relación eager load correspondiente.
