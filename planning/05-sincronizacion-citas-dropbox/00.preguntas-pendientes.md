## Pregunta 1 — Valores posibles del campo `status` ✅ RESPONDIDA

**Respuesta del usuario:**
- Valores: `"CANCELED"`, `"confirmed"`, `"completed"`, `"no-show"` (case-insensitive, normalizar con `strtoupper`)
- Si `status` está vacío (`""`) → tratar como `"confirmed"`

**Hallazgo adicional del JSON real:**
- El valor real observado es `"CANCELED"` (mayúsculas), no `"cancelled"`. El mapper debe normalizar con `strtolower()` para ser robusto ante variaciones.

**Impacto en implementación:** Ver tabla de equivalencias actualizada en Tarea 5.4.

## Pregunta 2 — Comportamiento ante `archived: true` ✅ RESPONDIDA

**Respuesta del usuario:** Opciones A + C combinadas:
- **A)** Mover el Lead al stage de perdido/cancelado (no eliminar)
- **C)** Agregar tag "Cancelado" al Lead

**Comportamiento adicional — `status: "CANCELED"`:**
- Igual que `archived: true`: mover al stage cancelado + agregar tag "Cancelado"
- La Activity NO se elimina, queda como historial

**Aclaración importante:** `archived` y `status: "CANCELED"` son mecanismos independientes. Un evento puede tener `archived: false` pero `status: "CANCELED"` (como se vio en el JSON real). Ambos deben disparar el mismo flujo de cancelación.

## Pregunta 3 — `owner._id` como `unique_id` ✅ RESPONDIDA

**Respuesta del usuario:** Solo para SMD. Continuar usando `unique_id` en la tabla `doctors`.

**Hallazgo crítico del JSON real — `owner` puede ser string:**
```json
// Evento normal (owner es objeto):
"owner": { "_id": "6525b4de...", "name": "Nuevo", "lastName": "Medico", "phone": "76123456", ... }

// Evento cancelado (owner es solo el ID como string):
"owner": "69bd9a6a7549b10008e0ac6b"
```

El código debe manejar ambos casos:
```php
private function parseOwner(mixed $owner): array
{
    if (is_string($owner)) {
        return ['_id' => $owner, 'name' => null, 'lastName' => null, 'phone' => null];
    }
    return [
        '_id'      => $owner['_id']      ?? null,
        'name'     => $owner['name']     ?? null,
        'lastName' => $owner['lastName'] ?? null,
        'phone'    => $owner['phone']    ?? null,
    ];
}
```

## Pregunta 4 — Crear paciente automáticamente ✅ RESPONDIDA

**Respuesta del usuario:**
1. Buscar primero en SOFO CRM (tabla `persons`) por teléfono
2. Si no existe localmente → crear con **teléfono como prioridad** + registrar los demás datos disponibles (nombre, apellido, fecha de nacimiento, `_id` SMD)
3. Si no hay teléfono en el JSON → buscar por `_id` SMD (`smd_patient_id`) o por nombre completo como fallback

**Hallazgo del JSON real — `attendances` sin `phone`:**
```json
// Evento cancelado: attendances sin campo phone
{
  "_id": "69bd9bed7549b10008e0ae98",
  "name": "Paciente",
  "lastName": "1",
  "fullName": "Paciente 1",
  "age": null
  // ← SIN phone, SIN birthday, SIN type
}
```

Búsqueda de paciente: teléfono → `smd_patient_id` (`_id` del asistente) → nombre completo.

## Pregunta 5 — `summary` → `Product` ✅ RESPONDIDA

**Respuesta del usuario:** NO mapear a Product.

`summary` = **Motivo de consulta** (`Activity.reason` en el CRM). Se guarda en el campo `reason` de la Activity, no como product vinculado al Lead.
