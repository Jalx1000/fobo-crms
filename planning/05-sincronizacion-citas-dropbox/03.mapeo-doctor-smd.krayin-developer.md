## Objetivo

Mejorar `resolveDoctor()` en `IncomingAppointmentService` para que use `owner.phone` del JSON SMD como segundo criterio de búsqueda. Definir qué pasa cuando el doctor no existe. Evaluar si guardar `owner._id` como `unique_id` es suficiente o si se necesita una columna `smd_physician_id` separada.

---

## Estado actual de `resolveDoctor()`

```php
private function resolveDoctor(array $data): object
{
    // Búsqueda 1: por unique_id (= owner._id de SMD)
    $doctor = $data['doctor_external_id']
        ? $this->doctorRepository->findOneByField('unique_id', $data['doctor_external_id'])
        : null;

    if (! $doctor) {
        // Búsqueda 2: por nombre exacto
        $doctor = $this->doctorRepository->findOneByField('name', $data['doctor_name'])
            ?? $this->doctorRepository->create([...]);

        // Backfill unique_id si el doctor existía sin él
        if ($data['doctor_external_id'] && ! $doctor->unique_id) {
            $this->doctorRepository->update(['unique_id' => $data['doctor_external_id']], $doctor->id);
        }
    }

    return $doctor;
}
```

### Problema

El JSON de Dropbox incluye `owner.phone` (`"76123456"`), pero `resolveDoctor()` nunca lo usa. Si un doctor fue creado manualmente en el CRM con su teléfono pero sin `unique_id`, el sistema crea un doctor duplicado en lugar de matchear el existente.

No existe columna `phone` ni `smd_physician_id`.

---

## Análisis: `unique_id` vs `smd_physician_id`

| Opción | Pros | Contras |
|--------|------|---------|
| Reutilizar `unique_id` (actual) | Sin migración | `unique_id` es semánticamente genérico; podría usarse para otros sistemas |
| Nueva columna `smd_physician_id` | Semántica clara, no rompe uso actual de `unique_id` | Requiere migración + actualizar `resolveDoctor()` |
| Columna `phone` en `doctors` | Permite búsqueda por teléfono sin SMD | Duplica datos si el doctor tiene múltiples teléfonos |

**Decisión recomendada:** Agregar columna `phone` a `doctors`. Es el campo más natural para matchear con `owner.phone`. Si el doctor ya tiene `unique_id` apuntando al `owner._id`, la búsqueda por `unique_id` sigue siendo la primera opción (más precisa).

## `resolveDoctor()` mejorado

```php
private function resolveDoctor(array $data): object
{
    // Búsqueda 1 (más precisa): por unique_id (owner._id de SMD)
    if ($data['doctor_external_id']) {
        $doctor = $this->doctorRepository->findOneByField('unique_id', $data['doctor_external_id']);
        if ($doctor) {
            return $this->syncDoctorPhone($doctor, $data['doctor_phone'] ?? null);
        }
    }

    // Búsqueda 2: por teléfono (si el doctor existe pero no tiene unique_id todavía)
    if (! empty($data['doctor_phone'])) {
        $doctor = $this->doctorRepository->findOneByField('phone', $data['doctor_phone']);
        if ($doctor) {
            // Backfill unique_id
            if ($data['doctor_external_id'] && ! $doctor->unique_id) {
                $this->doctorRepository->update([
                    'unique_id' => $data['doctor_external_id'],
                ], $doctor->id);
                $doctor = $this->doctorRepository->find($doctor->id);
            }
            return $doctor;
        }
    }

    // Búsqueda 3: por nombre exacto (fallback)
    if (! empty($data['doctor_name'])) {
        $doctor = $this->doctorRepository->findOneByField('name', $data['doctor_name']);
        if ($doctor) {
            $this->backfillDoctorIds($doctor, $data);
            return $doctor;
        }
    }

    // Sin match: crear doctor nuevo
    return $this->createDoctorFromSmd($data);
}

private function createDoctorFromSmd(array $data): object
{
    Log::warning('[IncomingAppointment] Doctor SMD no encontrado en CRM, creando nuevo', [
        'doctor_name'  => $data['doctor_name'],
        'doctor_phone' => $data['doctor_phone'] ?? null,
        'unique_id'    => $data['doctor_external_id'],
    ]);

    return $this->doctorRepository->create([
        'name'      => $data['doctor_name'] ?: 'Doctor Externo',
        'unique_id' => $data['doctor_external_id'],
        'phone'     => $data['doctor_phone'] ?? null,
        'email'     => $data['doctor_email'] ?? null,
        'is_active' => true,
    ]);
}

private function syncDoctorPhone(object $doctor, ?string $phone): object
{
    if ($phone && ! $doctor->phone) {
        $this->doctorRepository->update(['phone' => $phone], $doctor->id);
        return $this->doctorRepository->find($doctor->id);
    }
    return $doctor;
}

private function backfillDoctorIds(object $doctor, array $data): void
{
    $updates = [];

    if ($data['doctor_external_id'] && ! $doctor->unique_id) {
        $updates['unique_id'] = $data['doctor_external_id'];
    }

    if (! empty($data['doctor_phone']) && ! $doctor->phone) {
        $updates['phone'] = $data['doctor_phone'];
    }

    if (! empty($updates)) {
        $this->doctorRepository->update($updates, $doctor->id);
    }
}
```

## Qué pasa si el doctor no existe en el CRM

| Escenario | Comportamiento recomendado |
|-----------|---------------------------|
| Doctor nuevo en SMD, no existe en CRM | Crear automáticamente con `is_active = true`. Loguear como warning para que el admin pueda completar su perfil. |
| Doctor existe en CRM por nombre pero sin `unique_id` | Matchear por nombre, hacer backfill de `unique_id` y `phone`. |
| Doctor existe en CRM con teléfono pero sin `unique_id` | Matchear por `phone`, hacer backfill de `unique_id`. |
| Nombre del doctor en SMD está vacío y no hay teléfono | Asignar a `Doctor Externo` (id configurable). Loguear error. |

### Doctor default para casos sin match

```php
// config/smd.php
'fallback_doctor_id' => env('SMD_FALLBACK_DOCTOR_ID', null),
```

Si `fallback_doctor_id` está configurado y el doctor no se encuentra por ningún criterio, asignar ese doctor en lugar de crear uno nuevo. Si no está configurado, crear doctor nuevo.

---

## ¿Guardar `owner._id` como `smd_physician_id` separado?

No es necesario por ahora. El campo `unique_id` ya cumple esa función en el CRM. Si en el futuro el CRM necesita integrarse con otro sistema externo y `unique_id` ya está ocupado, se crea una nueva columna. La pregunta está listada en `00.preguntas-pendientes.md`.
