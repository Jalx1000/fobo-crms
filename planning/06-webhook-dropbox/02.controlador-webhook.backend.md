## Método `verify()` — Handshake GET

Dropbox envía: `GET /api/webhooks/dropbox?challenge=abc123`

El servidor debe responder exactamente con el valor del parámetro `challenge` como texto plano.

```php
public function verify(Request $request): Response
{
    $challenge = $request->query('challenge', '');

    return response($challenge, 200)
        ->header('Content-Type', 'text/plain');
}
```

Sin este método, el registro del webhook en el Developer Console fallará.

## Método `handle()` — Notificación POST

Dropbox envía:
```json
POST /api/webhooks/dropbox
X-Dropbox-Signature: <hmac_sha256(app_secret, raw_body)>

{
  "list_folder": { "accounts": ["dbid:..."] },
  "delta": { "users": [123456789] }
}
```

### Verificación de firma

```php
public function handle(Request $request): JsonResponse
{
    $appSecret = config('smd.dropbox.app_secret');
    $signature = $request->header('X-Dropbox-Signature', '');
    $body      = $request->getContent();

    $expected = hash_hmac('sha256', $body, $appSecret);

    if (! hash_equals($expected, $signature)) {
        Log::warning('[Dropbox Webhook] Firma inválida', [
            'ip'        => $request->ip(),
            'signature' => substr($signature, 0, 16) . '...',
        ]);

        return response()->json(['message' => 'Forbidden'], 403);
    }

    Log::info('[Dropbox Webhook] Notificación recibida', ['ip' => $request->ip()]);

    ProcessDropboxNotification::dispatch();

    return response()->json(['ok' => true], 200);
}
```

### Puntos clave de implementación

1. **Leer el body crudo antes de cualquier parsing**: `$request->getContent()` devuelve el body sin modificar. Si se usa `$request->json()` o `$request->all()` antes, el body puede estar ya parseado y la firma fallará.

2. **`hash_equals` es obligatorio**: previene timing attacks. No usar `===` directo.

3. **No procesar el payload del webhook**: el JSON del POST de Dropbox solo contiene IDs de cuentas — no contiene los archivos modificados. Lo relevante es simplemente que ocurrió un cambio. El job es quien llama a Dropbox para saber qué cambió.

4. **Responder 200 antes de cualquier lógica pesada**: `dispatch()` encola el job sin bloquearse si la cola está configurada con un driver real (database, Redis). Con `QUEUE_CONNECTION=sync` se ejecutaría en la misma request — verificar la configuración del entorno antes del deploy.

## Agregar `app_secret` al config `smd.php`

Actualizar `config/smd.php` para incluir:

```php
'dropbox' => [
    'access_token'        => env('DROPBOX_ACCESS_TOKEN'),
    'appointments_folder' => env('DROPBOX_APPOINTMENTS_FOLDER', '/smd-events'),
    'app_secret'          => env('DROPBOX_APP_SECRET'),   // ← agregar
],
```

## Patrón del controlador existente

El `ShareMeDataWebhookController` verifica un token simple con `hash_equals` (línea 23). El `DropboxWebhookController` sigue el mismo patrón pero con HMAC en lugar de token plano. Ambos usan `Log::warning` para tokens inválidos y devuelven JSON.
